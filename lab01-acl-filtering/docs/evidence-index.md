# 证据来源与完整性

## 三种材料类别

1. 原始附件：`evidence/original-text/` 的 3 个文本附件与 `evidence/screenshots/` 的 16 张实验截图，字节内容不改。原始文件名及 SHA-256 见 `evidence/source-index.csv`。
2. 对话输出摘录：`evidence/terminal/` 的 V01–V06、D01–D02，取自实验者粘贴的实际输出，按主题整理，非自动会话录像。V04 去掉了错粘到缓冲区的残留文字，D01 仅保留关键表项；不存在新增的成功数据。
3. 派生材料：报告、拓扑图、复现配置和排障说明，由上述材料与已记录的执行过程整理，不冒充设备原始导出。

两个带有其他工作背景的截图 image(3).png、image(6).png 未收入公开文件包。课程 PDF 仅作为参考，不随包重新分发。现有截图主要属于排障阶段，不能冒充最终完整拓扑截图。

## 尚未收到的原始文件

- 最终 Lab2_ACL.gns3 或 GNS3 便携工程导出。
- 设备内部真实导出的 Lab2_ACL.rsc 与 Lab2_ACL.backup。
- 实际 PCAP 文件、实验最初至最后的完整自动会话记录。
- 最终完整 GNS3 拓扑截图。

文件列表输出能够证明设备内部生成过导出与备份，但不能替代这些文件的字节内容。本包不生成伪造 .gns3 工程或同名设备备份。

## 哈希的用途

在仓库根目录运行 `python3 scripts/verify_evidence.py`，可检查原始附件的字节完整性。哈希只帮助确认打包后未变更，不证明截图产生时刻、作者身份或记录涵盖全部操作。

`SHA256SUMS` 是发布包文件快照。后续补入仓库链接或截图会改变文件，应重新生成清单并如实提交，不能把新的整理提交倒填为实验时间。
